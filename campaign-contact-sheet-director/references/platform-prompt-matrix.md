# Platform Prompt Matrix

这份文档定义怎样把同一套 contact sheet 方案翻译到不同平台，而不是机械翻译。

## 1. Prompt 组装顺序

先写整套锚点，再写逐格差异。

```text
Master Anchor
+ 场景与主体
+ 品牌气质
+ 光线系统
+ 镜头系统
+ 色彩与材质
+ 构图纪律
+ 版式/裁切约束

Frame Delta
+ 该格角色
+ shot type
+ 距离与角度变化
+ 动作或状态
+ 需要保留的锚点
+ 该格专属 negative risks
```

## 2. Midjourney

- 适合：整体气氛、构图统一、风格探索。
- 写法：把 `Master Anchor` 放前半段，把 `Frame Delta` 放后半段。
- 额外提醒：用简洁但高密度的画面语义，不要把 9 格一次塞进一个 prompt。
- 建议：每格单独生成，但复用同一锚点骨架。

## 3. 即梦

- 适合：中文语义明确、商业氛围、较完整场景描述。
- 写法：先中文叙述锚点，再加该格职责。
- 额外提醒：强调“同一 campaign 的第 X 格”，有助于保持连续性。
- 建议：写清镜头高度、材质、人物动作和留白区。

## 4. 可灵

- 适合：动作、叙事感、空间流动性较强的画面。
- 写法：保留锚点，但对 motion、人物行为、镜头推拉关系写得更明确。
- 额外提醒：当格子承担 motion 任务时，要写物理路径和动势方向。

## 5. Nano Banana

- 适合：中文概念探索、风格尝试、快速变体。
- 写法：减少平台外参数，强化“画面功能”和“主体关系”。
- 额外提醒：避免堆叠太多抽象形容词，否则容易把多格系统做散。

## 6. Seedream

- 适合：商业视觉、物体质感、相对稳定的构图任务。
- 写法：把主体结构、背景层次、光线与材质写得更工程化。
- 额外提醒：需要文字或 logo 时，优先写“留出后期字区”。

## 7. 通用中文模型

- 适合：兜底平台。
- 写法：使用“主体 + 场景 + 光线 + 镜头 + 构图 + 材质 + 留白 + 风险限制”的完整句式。
- 额外提醒：不要假设支持复杂参数；靠语义控制一致性。

## 8. 推荐输出字段

每格平台 prompt 统一返回：

```text
- Midjourney：
- 即梦：
- 可灵：
- Nano Banana：
- Seedream：
- 通用中文模型：
- Negative risks：
```

## 9. Negative risks 应包含什么

- 容易跑成其他品类
- 透视、接触面、反射错误
- 风格漂移
- 人物/手部/脚部失败
- label、文字、logo 乱码
- 空间比例、层高、装置尺度错误
- 社媒裁切后主体被切断

## 10. Fail if

- 每个平台只是同一句话换个语言。
- 没有 `Master Anchor`，只有逐格 prompt。
- 没有写该格相对整套的功能差异。
- 没有单独写 negative risks。
