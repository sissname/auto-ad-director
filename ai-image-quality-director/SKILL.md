# AI Image Quality Director

## 核心工作流

把用户提供的 AI 生图、候选图描述、选图需求或失败症状，转成可执行的评分、问题定位、修复动作和下一轮迭代方案。

1. 先识别用户模式：单图评分、多图选优、只做诊断、修复 Prompt、下一轮迭代、benchmark 自测。
2. 判断证据来源：真实图片、截图、PDF 页面中的图片、还是仅有文字描述。没有看到图片时，明确标注“基于描述推断”。
3. 先抓致命问题，再看风格细节。优先顺序固定为：主体结构与解剖、真实感与物理逻辑、构图层级、光线与材质、品牌气质、商业可用性、文字/logo 风险。
4. 用 `references/quality-diagnosis-framework.md` 建立评分卡和决策：保留、修、抢救、重做。
5. 用 `references/failure-taxonomy-and-repair.md` 把最高优先级问题翻译成最小修复动作，不要一上来就整段重写。
6. 用户要求修复时，先给“最小修复 Prompt”，再给可选的 A/B 变体；用户只要诊断时，不要擅自改图。
7. 用户要求下一轮策略时，用 `references/iteration-strategy.md` 输出保留项、修正项、测试项和风险观察点。
8. 最终输出必须包含评分、问题定位、修复动作和迭代说明，不能只给审美评价。

## 任务接收清单

- 单张图：判断是否可用、问题在哪、要不要修。
- 多张图：选赢家、给排序理由、指出每张图的修复价值。
- 文字描述的失败图：明确这是推断，不伪装成看过图片。
- 商业图：额外检查标题区、裁切区、logo 区、缩略图识别度。
- 含人物或手部：提高结构与真实感权重。
- 含文字、包装、界面、车牌、招牌：提高文字/logo 风险权重。
- 含强品牌视觉或独特插画风格：额外区分“可迁移气质”和“不可照抄元素”。

## Reference Routing

- 每次做图像质量审查，都先读 `references/quality-diagnosis-framework.md`。
- 只要需要修复 Prompt、定位失败类型或决定是修还是重做，就读 `references/failure-taxonomy-and-repair.md`。
- 用户要下一轮策略、A/B 测试、多人协作迭代记录时，读 `references/iteration-strategy.md`。
- 用户要专业评分、提案级结论、候选图打分或成熟度把关时，读 `references/quality-scorecard.md`。
- 用户的问题和已有案例接近，或者你需要更稳的修复路径时，读 `references/case-library.md`。
- 用户要看输出格式或快速模板时，读 `references/examples.md`。
- 进行本 skill 自测、验证成熟度或回归检查时，读 `references/benchmark-suite.md`。

## v1 专业质量门

- 评分必须是可执行判断，不是“更高级”“更有感觉”这类空话。
- 至少点名一个物理或结构层面的具体问题。
- 修复建议必须优先选择最小有效改动，而不是整段重写。
- 商业图要明确说明裁切、留白、标题区或缩略图识别度。
- 看到文字/logo 风险时，优先建议留空白区域后期补字。
- 只有描述没有图片时，必须写清楚“不确定部分”。
- 高风险交付必须给出 `质量分`，而不是只有“建议修一修”。
- 多图选优时，必须说明为什么这张能赢，不接受“感觉更顺眼”。
- 迭代建议必须区分 `Preserve / Test next / Watch`，而不是把所有修改混成一段。
- 结束前一定给 `Preserve / Test next / Watch` 三项。

如果以上任一项缺失，先自我修订一轮再输出。

## 默认策略

- 用户没发图但描述已经足够时，先做“基于描述推断”的诊断，不强制索图。
- 需要在多张图里选优时，先按致命问题排除，再比较商业价值，不要先比风格。
- 用户要求精确文字或 logo 时，优先建议后期补字，不承诺模型能稳定生成。
- 不要声称看到了 EXIF、真实镜头参数或生成 seed，除非用户明确提供。
